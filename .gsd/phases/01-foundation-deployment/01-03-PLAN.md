<task type="checkpoint:decision" gate="blocking">
  <decision>Is STRATO SFTP full-site deployment part of V1, or deferred in favor of GitHub Pages-only?</decision>
  <context>
    Current artifacts are slightly inconsistent:
    - Roadmap and requirements mention STRATO SFTP deployment
    - Phase 01 context suggests GitHub Pages-only for V1
    This decision changes what “done” means for Phase 1.
  </context>
  <options>
    <option id="strato-v1">
      <name>Include STRATO SFTP deployment in V1</name>
      <pros>Matches stated deployment requirement; owners can deploy without GitHub; more independent</pros>
      <cons>Needs credentials + tool choice (WinSCP/OpenSSH); higher setup friction</cons>
    </option>
    <option id="pages-v1">
      <name>GitHub Pages-only for V1; STRATO deferred to V1.X/V2</name>
      <pros>Fastest path to a reviewable live site; minimal owner setup</pros>
      <cons>Owners must rely on Git/GitHub for publishing; STRATO work postponed</cons>
    </option>
  </options>
  <resume-signal>Select: strato-v1 or pages-v1</resume-signal>

  <name>Implement STRATO SFTP deploy script (only if decision is strato-v1)</name>
  <files>site/scripts/deploy-strato.ps1, notes/Deployment.md</files>
  <action>
    If the decision is strato-v1:
    - Create site/scripts/deploy-strato.ps1 that uploads site/build/dist to STRATO via SFTP.
    - Prefer WinSCP.com for password-based SFTP automation; fall back to key-based OpenSSH if available.
    - Accept credentials via parameters or environment variables (avoid committing secrets).
    - Update notes/Deployment.md with exact usage instructions.

    If the decision is pages-v1:
    - Do not create deploy-strato.ps1.
    - Update notes/Deployment.md to explicitly document Pages as the V1 publishing mechanism and mark STRATO as deferred.
  </action>
  <verify>test ! -f site/scripts/deploy-strato.ps1 || grep -RIn "WinSCP" site/scripts/deploy-strato.ps1 >/dev/null</verify>

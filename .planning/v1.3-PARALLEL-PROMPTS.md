# v1.3 Parallel Execution Prompts

## Parallel Working Model

All 3 epic skins live on the **same branch** in separate directories — no branch switching, no worktrees. Like `review/all-designs` but for source files.

**Important operational note:** directory ownership is parallel-safe, but
browser-driven review or Playwright work is **not** parallel-safe on a single
machine if all agents share one local browser session. In that setup, serialize
the visual-audit portions even if source work is split across directories.

```
site/epic/a/    ← Agent A's territory (8 HTML pages + CSS)
site/epic/b/    ← Agent B's territory
site/epic/c/    ← Agent C's territory
site/public/    ← Shared assets (img/, js/, data/) — read-only
```

**Rules:**
- Commit only files in YOUR directory (`site/epic/{letter}/`)
- Never modify `site/public/`, `site/src/`, or another agent's `site/epic/` directory
- Reference shared assets via relative paths (`../public/img/`, `../public/js/`, etc.)
- Each directory is a self-contained static site: 8 HTML pages + base.css + tailwind.css
- The shared comparison/start page is not owned by a skin prompt; keep the
  picker/review surface as shared infrastructure

## Prerequisite

Phase 26 (Epic Directions) must be complete. It produces:
- `.planning/phases/26-epic-directions/26-EPIC-DIRECTIONS.md` — all 3 structural signatures
- `site/epic/{a,b,c}/` directories scaffolded

## Prompt 1: Epic Skin A (Phase 27)

```
/gsd:research-phase 27

## Kickoff — you can skip discuss-phase, everything is decided below.

### What this project is
teilAuto Mössingen — a static HTML+Tailwind CSS website for a small family-run carsharing cooperative in southern Germany. ~60 members, 2 vehicles, phone-only booking. The site's job: attract ~20 new members who fit the "Zweitwagen" (second car) profile without generating false-positive phone calls from tire-kickers.

### What you're doing
You are ONE of THREE parallel agents, each building an "epic skin" — a structurally distinct design for the same 8-page site. You are Agent A. Agents B and C are working simultaneously in their own directories. You will never see their work and they will never see yours.

### Your design direction
Read `.planning/phases/26-epic-directions/26-EPIC-DIRECTIONS.md` — section "Epic Direction A" — for your structural signature: hero composition, nav pattern, section ordering, visual signature element, copy strategy, and information density.

### Parallel work rules
- Your files live in `site/epic/a/` — commit ONLY files in this directory
- Shared assets (images, JS, pricing data) are at `site/public/` — read-only, reference via relative paths
- Never touch `site/epic/b/`, `site/epic/c/`, or `site/src/`

### Constraints (all designs)
1. HTML + Tailwind CSS v4 only. `@theme` block for your design tokens.
2. Google Fonts CDN (must support German characters: ä, ö, ü, ß)
3. 8 pages: index, preise, fahrzeuge, geschaeftskunden, ueber-uns, mitglied-werden, impressum, datenschutz
4. Phone CTA only: 07473-922202. No email, no forms.
5. Membership gate: clearly communicate this is membership-based, not one-time rental
6. Content from verified sources only — snappier wording OK, invented claims not OK
7. Primary persona: Simone (young mother, needs car during day while partner's car is at work)
8. Responsive: 375px / 768px / 1280px+
9. Legal pages (impressum, datenschutz) must accommodate long-form text
10. Pricing data via `pricing.json` + `pricing.js` pattern from `site/public/`
11. MapLibre map on fahrzeuge.html (420-520px container)
12. German language, Sie-Ansprache, sachlich+freundlich tone

### What to research
Focus on HOW to implement YOUR specific direction's structural elements:
- CSS/Tailwind techniques for your assigned hero composition type
- Your nav pattern implementation (responsive behavior, accessibility)
- Your visual signature element (CSS-only or SVG approach)
- Google Fonts that match your direction's aesthetic
- Responsive strategy for your information density level
- Any v1.2 code worth salvaging (see `site/src/` for the v1.2 codebase)

### Reference docs
- `.planning/phases/26-epic-directions/26-EPIC-DIRECTIONS.md` — YOUR direction spec
- `.planning/v1.3-MILESTONE-BRIEF.md` — full milestone context + epic skin standard
- `.planning/ROADMAP.md` — Phase 27 success criteria (8 items)
- `.planning/PROJECT.md` — project context, personas, constraints
- `site/src/` — v1.2 Design C codebase (the current chroma)

### Output
Write to: `.planning/phases/27-epic-skin-a/27-RESEARCH.md`
Then: `/gsd:plan-phase 27 --auto` to plan and execute.
```

## Execution Flow

```
Phase 26 (single session — write epic direction specs)
    │
    │  produces 26-EPIC-DIRECTIONS.md + scaffolds site/epic/{a,b,c}/
    │
    ├──→ Prompt 1 (session A) ─┐
    ├──→ Prompt 2 (session B) ──┼── 3 terminals, same repo, same branch
    └──→ Prompt 3 (session C) ─┘   each agent: research → plan → execute
                                │
                          Phase 30 (single session — shared picker + epic review)
                                │
                          Phase 31 (single session — Design D in site/epic/d/)
```

**No worktrees needed.** All 3 agents work on the same branch, same checkout. Each commits only `site/epic/{letter}/` files — no conflicts possible.

# v1.4 Sequential Execution Prompts

These prompts assume the shared-browser constraint: **A, B, and C polish phases
must not run in parallel.**

Run them in order after Phase 32 baseline work is done.

The shared comparison surface keeps the old review model intact: one branch,
multiple versions, shared start page/version picker first. Phase 32 and Phase
36 own that surface. Phases 33-35 must not quietly invent a competing one.

## Prompt 1: Phase 33 - Design A Polish

```text
/gsd:plan-phase 33

This is a sequential polish phase for `site/epic/a/`. Do not assume any other
browser-driven polish phase is running at the same time, and do not try to
parallelize this with B or C.

Context:
- Shared milestone brief: `@.planning/v1.4-MILESTONE-BRIEF.md`
- Draft requirements: `@.planning/v1.4-REQUIREMENTS-DRAFT.md`
- Draft roadmap: `@.planning/v1.4-ROADMAP-DRAFT.md`
- v1.0 requirements floor: `@.planning/milestones/v1.0-REQUIREMENTS.md`
- v1.0 roadmap context: `@.planning/milestones/v1.0-ROADMAP.md`

Scope:
- Review every page in `http://127.0.0.1:5500/site/epic/a/` at 375px, 768px,
  and 1280px using Playwright.
- Check both visual execution and compliance with the v1.0 requirements floor.
- Before each fix pass, write a TODO list with page, location, and issue.
- Then fix everything found in one batch.
- Repeat review -> TODO -> fix -> verify until no further obvious issues remain
  or 5 iterations have been completed.
- If 5 iterations are reached and non-nitpick issues remain, stop and wait for
  user input before another loop block.

Guardrails:
- Stay inside `site/epic/a/` unless you hit an explicitly shared blocker.
- If you discover shared repo/planning drift, report it as a blocker instead of
  absorbing it into the skin work.
- Do not create or repurpose the shared start page/version picker from this
  phase; shared review-surface work belongs to Phases 32 and 36.
- This is not a redesign phase; keep the structural identity of Design A intact.
```

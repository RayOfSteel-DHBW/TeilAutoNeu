Run up to 5 full iterations. Each iteration must follow the exact order below:

**A. Review all 8 pages with Playwright**

- Review `index.html`, `preise.html`, `fahrzeuge.html`, `geschaeftskunden.html`, `ueber-uns.html`, `mitglied-werden.html`, `impressum.html`, and `datenschutz.html`.
- Use `375px`, `768px`, and `1280px` viewports on every executed iteration.
- Capture enough full-page evidence to inspect above-the-fold and lower-page sections.
- Check visual quality and runtime behavior together:
  - no horizontal overflow
  - no clipped or unreadable text
  - nav renders correctly at each breakpoint
  - footer and mobile phone CTA do not overlap content
  - pricing content renders on `preise.html`
  - fleet map renders with visible attribution on `fahrzeuge.html`
  - FAQ / accordion behavior still works where present
  - broken image, console, and obvious link issues are surfaced

**B. Audit against the v1.0 requirements floor**

Limit the audit to requirements that are page-owned and testable inside `site/epic/a/`. At minimum, check:

- Sitewide: `teilAuto` casing, phone format `07473-922202`, Sie-Ansprache, no forms or email signup, no false capability claims, no TODO/placeholder leaks, semantic page structure, working nav/footer links.
- Homepage: value prop works for the Zweitwagen persona, membership gate is clear, FAQ exists, local area framing remains present.
- Preise: value-first framing, only light pricing presentation, disclaimer present, no full tariff dump.
- Fahrzeuge: two current vehicles, interactive map with active locations and planned Don Bosco, attribution visible.
- Mitglied werden: phone-only conversion path and expectations remain explicit.
- Impressum / Datenschutz: legal pages are readable and intact.

If you find something that belongs to shared phases rather than Design A ownership, log it as a blocker and stop rather than fixing it here.

**C. Write the TODO list before editing**

Before making any source changes, append a new section to `33-ITERATION-LOG.md` using this structure:

`## Iteration N TODO`

| Page | Location | Issue | Requirement/Gate | Severity | Planned fix |
|------|----------|-------|------------------|----------|-------------|

- Include every non-nitpick issue found in the review.
- `Severity` must be one of: `blocker`, `major`, `minor`, `nitpick`.
- Anything that breaks layout, runtime behavior, conversion clarity, legal readability, or a v1.0 requirement is not a nitpick.

If the review finds no issues, still append the section and record `Clean pass - no issues found` before ending the loop.

**D. Apply one batched fix pass**

- Fix every item from that iteration in one batch.
- Stay inside `site/epic/a/` and phase-local docs only.
- Rebuild Tailwind after HTML/CSS changes:
  `cd site && npx @tailwindcss/cli -i epic/a/style.css -o epic/a/tailwind-out.css --content "epic/a/**/*.html"`
- If JS changed, rerun the affected page interactions after the build.

**E. Verify the batch**

- Re-run Playwright on every touched page at all three breakpoints.
- If a shared CSS or nav change could affect multiple pages, re-run the full 8-page sweep immediately.
- Append a short verification result under the same iteration in `33-ITERATION-LOG.md`: what was fixed, what passed, what remains.

**F. Stop conditions**

- Stop early on the first clean pass.
- If Iteration 5 finishes and any non-nitpick issues remain, STOP and wait for user input. Record the hold clearly in `33-01-SUMMARY.md`.
- Do not start a 6th iteration on your own.

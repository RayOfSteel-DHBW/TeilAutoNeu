## Common Pitfalls

### Pitfall 1: Partial removal leaving orphaned references

**What goes wrong:** Removing the Webanalyse section but leaving the consent withdrawal paragraph in "Ihre Rechte" (or vice versa). The page would then have a rights paragraph referencing a service that is no longer disclosed.

**How to avoid:** Execute all three removals as a unit. After build, verify that neither "Google Analytics" nor "kuenftig" nor "Einwilligung" appears in the built output. (Exception: "Widerspruch" in Art. 21 is about legitimate interest, not consent — keep that.)

**Grep check after build:**
```bash
cd site && npm run build
grep -i "google analytics" build/dist/datenschutz.html  # expect 0 matches
grep "künftig" build/dist/datenschutz.html              # expect 0 matches
grep "Einwilligung" build/dist/datenschutz.html         # expect 0 matches
grep "Art. 20" build/dist/datenschutz.html              # expect 0 matches
```

### Pitfall 2: Removing too much — breaking required DSGVO content

**What goes wrong:** Removing more than the three specified fragments, accidentally deleting mandatory Art. 13 content (Verantwortlicher, legal bases, rights list, complaint right).

**How to avoid:** Only target the three explicitly identified fragments. Verify retained sections are intact after build.

**Grep check after build:**
```bash
grep "Art. 6" build/dist/datenschutz.html    # must exist (STRATO + OpenFreeMap)
grep "OpenFreeMap" build/dist/datenschutz.html  # must exist
grep "STRATO" build/dist/datenschutz.html    # must exist
grep "Art. 15" build/dist/datenschutz.html   # must exist (rights)
grep "Beschwerderecht\|Landesbeauftragten" build/dist/datenschutz.html  # must exist
```

### Pitfall 3: Forgetting to rebuild before verifying

**What goes wrong:** Checking `site/src/datenschutz.html` directly instead of `site/build/dist/datenschutz.html`. The Tera build step is required to produce the final output that will be deployed.

**How to avoid:** Always run `npm run build` from the `site/` directory before verification. Verification reads `build/dist/`, not `src/`.

### Pitfall 4: Breaking the "Ihre Rechte" list formatting

**What goes wrong:** Removing the Art. 20 `<li>` leaves a gap in the numbered-rights list that disrupts the visual checkmark pattern.

**How to avoid:** The list uses visual checkmarks (`&#10003;`) not `<ol>` numbering, so removing a list item does not break sequence numbering. Just remove the `<li>` cleanly. Remaining rights (Art. 15, 16, 17, 18, 21) remain complete.

## DSGVO Compliance After Changes

Confirming the simplified page remains Art. 13 DSGVO compliant:

| Art. 13 Requirement | Covered by | Remains after Phase 11? |
|--------------------|-----------|------------------------|
| Identity of controller | "Verantwortlicher" section | Yes |
| Contact details | Verantwortlicher (phone + email) | Yes |
| Legal basis (Art. 6) | Server-Logfiles + OpenFreeMap sections | Yes (both lit. f) |
| Data recipients | Implicitly STRATO AG (named) and OpenFreeMap | Yes |
| Retention period | "gemaess Aufbewahrungsfristen STRATO" | Yes |
| Data subject rights | "Ihre Rechte" — Art. 15, 16, 17, 18, 21 | Yes (5 rights remain) |
| Right to complain | "Beschwerderecht" section | Yes |
| Art. 20 portability | Only applies to consent/contract — not present | Correctly removed |
| Consent withdrawal | Only needed when consent-based processing exists | Correctly removed |

**Art. 20 note (MEDIUM confidence):** Art. 20 DSGVO (Datenuebertrabarkeit) applies only when processing is based on consent (Art. 6 lit. a) or contract (Art. 6 lit. b) AND is carried out by automated means. Since this site uses only lit. f (legitimate interest) for server logs and OpenFreeMap, Art. 20 does not apply. This is the consensus interpretation per standard German DSGVO commentary; removing it is legally correct, not a reduction in mandatory disclosures.

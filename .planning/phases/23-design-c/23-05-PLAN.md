This task uses the Playwright MCP (browser tools) to take screenshots, evaluate visual quality, and fix issues. This is an iterative process.

**Prerequisites:**
1. Ensure site is built: `cd site && npm run build`
2. Ensure live server is running at http://127.0.0.1:5500/site/build/dist/ (the user should start this if not running -- ask if needed)

**Audit process (repeat for each page):**

For each of the 8 pages:
1. Navigate to the page at each breakpoint using Playwright browser tools
2. Take a screenshot at each breakpoint (375px, 768px, 1280px)
3. Evaluate the screenshot for Direction C-specific issues:
   - **Layout breaks:** Elements overflowing viewport, horizontal scroll, misaligned grids
   - **Card visibility:** Can you distinguish sand cards (#f0e6d6) from cream background (#fdf6ee)? The warm shadow must provide sufficient separation
   - **Typography:** Headings should be Nunito (rounded terminals). Body should be DM Sans (clean geometric). No v1.1 fonts visible
   - **Color system:** Terracotta (#b5541a) accents only. No teal, no navy, no green, no cool tones
   - **Nav check:** Warm cream nav, terracotta logo in Nunito, phone pill button VISIBLE in nav, hamburger at 768px (lg collapse)
   - **Fixed bottom phone bar:** Visible at 375px and 768px as full-width pill button, hidden at 1280px. Must not overlap footer content
   - **Hero:** 70vh, centered, two pill CTA buttons, organic shapes visible but not overwhelming, warm gradient background
   - **Membership gate:** Warm standalone card (rounded-2xl) visible after hero on homepage (NOT a colored band)
   - **Interactive elements:** Map on fahrzeuge, pricing data on preise
   - **CTA blocks:** Terracotta section with white text and phone number on all non-legal pages
   - **Legal pages:** Clean prose, no CTA blocks, comfortable reading width, terracotta links
   - **Pill buttons:** All CTAs use rounded-full (NOT rounded-md or rounded-lg)
   - **No v1.1 artifacts:** Zero rounded-3xl, zero green colors, zero Source Sans 3 / Space Grotesk

4. If issues found, fix the source files, rebuild (`cd site && npm run build`), and re-screenshot to verify

**Breakpoint workflow:**
```
For width in [375, 768, 1280]:
  1. Resize browser to width x 900
  2. For page in [index, preise, fahrzeuge, geschaeftskunden, ueber-uns, mitglied-werden, impressum, datenschutz]:
    a. Navigate to http://127.0.0.1:5500/site/build/dist/{page}.html
    b. Take full-page screenshot
    c. Evaluate for Direction C-specific issues
    d. If issues: fix source, rebuild, re-screenshot
```

**Issue priorities (fix all):**
- P0: Page doesn't render, white screen, build error
- P1: Horizontal overflow, elements off-screen, unreadable text, wrong font family
- P2: Misaligned grid, wrong spacing, v1.1 styles leaking through, nav collapse wrong
- P3: Minor spacing tweaks, subtle alignment improvements, shadow rendering, card contrast

**Direction C anti-pattern checks (from 23-RESEARCH.md):**
- Any `rounded-3xl` on content containers? Change to `rounded-2xl`.
- Phone number MISSING from nav? Add it as pill button.
- Cool-toned fonts appearing? Replace with Nunito/DM Sans.
- `max-w-6xl` used? Fix to `max-w-5xl`.
- Cards missing shadows? Add `shadow-md`.
- Cool colors (teal, navy, green) appearing? Replace with terracotta/cream.
- `rounded-lg` or `rounded-md` on CTA buttons? Change to `rounded-full`.
- Alternating bands instead of cards? Replace with sand cards.

**Warm shadow fallback check:**
If `shadow-brand-primary/8` doesn't render properly (Tailwind v4 shadow-color support varies), use an arbitrary value shadow:
```html
class="shadow-[0_4px_6px_-1px_rgba(181,84,26,0.08),0_2px_4px_-2px_rgba(181,84,26,0.05)]"
```
Or simply use `shadow-md` without color tinting if the arbitrary value is too complex.

**After fixing all issues:**
- Rebuild: `cd site && npm run build`
- Take final screenshots at all 3 breakpoints for all 8 pages as evidence
- Commit all fixes

**IMPORTANT:** This task REQUIRES IMPL-06 (Frontend Design Plugin). Use the Playwright browser tools (browser_navigate, browser_resize, browser_take_screenshot, browser_snapshot) for visual auditing.

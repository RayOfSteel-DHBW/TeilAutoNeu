# Draft Roadmap: v1.4 Epic Skin Polish

**Prepared:** 2026-03-09
**Status:** Prepared, not yet promoted to active milestone files

## Milestone Goal

Turn the three epic skins into clean review candidates through bounded,
sequential visual+requirements iteration loops, while keeping shared repo and
planning housekeeping out of the skin-specific work and preserving the
one-branch start-page/version-picker review flow.

## Execution Model

**Sequential only.**

The local browser is a shared resource, so browser-driven audit phases must run:

1. Phase 32
2. Phase 33
3. Phase 34
4. Phase 35
5. Phase 36

No parallel polish execution is assumed.

## Phase Overview

### Phase 32: Polish Baseline & Review Surface

**Goal:** Remove shared repo/planning uncertainty before the skin-specific audit
loops start and lock down the shared comparison surface contract.

**Requirements:** BASE-01, BASE-02, BASE-03, AUDIT-04, LOOP-03

**Success Criteria**
1. Shared planning/docs reflect the actual A/B/C repo state.
2. Directory and page inventories exist for all three skins.
3. The canonical one-branch review model is documented: shared start
   page/version picker -> stable A/B/C paths.
4. Skin-specific phases are clearly scoped away from shared review-surface
   ownership.

### Phase 33: Epic Skin A Polish Loop

**Goal:** Bring `site/epic/a/` to review-ready quality through bounded iterative
visual+requirements review.

**Requirements:** AUDIT-01, AUDIT-02, AUDIT-03, LOOP-01, LOOP-02, READY-A-01

**Success Criteria**
1. All 8 A pages reviewed at 375/768/1280.
2. Each iteration creates a written TODO list before fixes.
3. Audit covers both visual issues and v1.0 requirement adherence.
4. The loop stops only on a clean pass or at the 5-iteration cap.
